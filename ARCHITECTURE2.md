# StartupBot — описание и архитектура

## Назначение

Telegram-бот для педагогического эксперимента на курсе «Основы технологического предпринимательства» (ДГТУ). Бот сравнивает эффективность трёх форматов работы студенческих команд над стартап-проектами:

| Группа | Описание |
|--------|----------|
| **H** | Только люди, без ИИ |
| **H+AI** | Студенты + ИИ-наставники (направляют мышление, не дают готовых ответов) |
| **AI-heavy** | Студенты + ИИ-команда (Аналитик, Стратег, Критик делают работу вместе со студентами) |

Бот собирает историю переписки, рефлексии и метрики активности для последующего анализа исследователем.

---

## Стек

- **python-telegram-bot 21** (async, ConversationHandler)
- **OpenAI API** (gpt-4o-mini по умолчанию, function calling, agentic loop)
- **SQLite** через `aiosqlite` (WAL-режим)
- **DuckDuckGo Search** (`ddgs`) — веб-поиск без API-ключа для Аналитика

## Структура файлов

```
startupbot/
├── main.py                      # точка входа, сборка Application, фоновый монитор
├── config.py                    # env-переменные, системные промпты всех ролей
├── db/
│   └── database.py              # Database: весь SQL, миграции, seed данных
├── handlers/
│   ├── student.py               # ConversationHandler для студентов
│   └── admin.py                 # команды преподавателя/исследователя
└── services/
    ├── ai_service.py            # простой AI-сервис для группы H+AI (один агент)
    ├── multi_agent_service.py   # MultiAgentService для AI-heavy (оркестратор + агенты)
    └── export_service.py        # экспорт данных в CSV/Excel
```

## Архитектура

### Поток сообщения студента

```
Студент пишет в Telegram
        │
        ▼
  handlers/student.py
  ConversationHandler
        │
        ├─── группа H → сообщение сохраняется, ответ не генерируется
        │
        ├─── группа H+AI → ai_service.py
        │         │  один агент (роль задана команде)
        │         │  системный промпт: наставник, не делает работу за студентов
        │         └─→ ответ → сохраняется в messages
        │
        └─── группа AI-heavy → multi_agent_service.py
                  │
                  ├─ Шаг 1: Оркестратор (LLM, temp=0)
                  │   смотрит последние 8 сообщений, выбирает кто отвечает
                  │   (Аналитик / Стратег / Критик / NONE)
                  │
                  └─ Шаг 2: выбранный агент отвечает
                      Аналитик: agentic loop с tool search_web (DuckDuckGo)
                      Стратег/Критик: прямой LLM-вызов
                      → ответ → сохраняется в messages
```

### База данных (SQLite)

```
agent_roles ──< prompt_versions   (версионирование промптов)
teams ──< students
teams ──< team_agents >── agent_roles  (состав AI-heavy команды)
iterations                             (занятия; только одно active)
students ──< messages ──< message_labels
students ──< reflections
session_events                         (включение/выключение агента, прочие события)
```

### Ключевые концепции

**Версионирование промптов** — при обновлении системного промпта старая версия деактивируется, создаётся новая. Каждое сообщение хранит `prompt_version_id`, что позволяет отследить, какой промпт использовался.

**Оркестратор** — лёгкий LLM-вызов (max_tokens=30, temp=0) определяет, кто из агентов должен ответить. Отвечает ровно один агент или никто (NONE для коротких подтверждений).

**Agentic loop для Аналитика** — Аналитик может вызывать `search_web` несколько раз через OpenAI function calling, прежде чем дать финальный ответ.

**Инактивность** — фоновая задача каждые N минут проверяет студентов AI-групп и уведомляет администраторов о неактивных.

## Роли агентов

| Роль | Группа H+AI | Группа AI-heavy |
|------|------------|-----------------|
| **Аналитик** | Задаёт вопросы, структурирует мышление | Ищет данные в интернете, приносит цифры |
| **Стратег** | Предлагает сценарии, студенты решают сами | Разрабатывает бизнес-модель, принимает решения |
| **Критик** | Формулирует проблемы, не даёт решений | Называет слабые места + предлагает улучшения |

## Команды

### Студент
- `/start` — регистрация по коду команды
- `/status` — текущее занятие и статус агента
- `/reflect` — рефлексия по итерации (вклад, когнитивная нагрузка, полезность ИИ)
- `/history` — история прошлых занятий с возможностью разметить сообщения

### Администратор (преподаватель/исследователь)
- Управление командами, студентами, занятиями
- Включение/выключение агента глобально или для конкретной команды
- Просмотр статистики, экспорт данных (CSV/Excel)
- Просмотр и редактирование системных промптов

## Конфигурация (.env)

| Переменная | Назначение |
|-----------|------------|
| `TELEGRAM_BOT_TOKEN` | токен бота |
| `OPENAI_API_KEY` | ключ OpenAI |
| `OPENAI_MODEL` | модель (по умолчанию `gpt-4o-mini`) |
| `DATABASE_PATH` | путь к SQLite файлу |
| `MAX_CONTEXT_MESSAGES` | глубина контекста (по умолчанию 20) |
| `INACTIVITY_ALERT_MINUTES` | порог неактивности (по умолчанию 20) |
| `ADMIN_TELEGRAM_IDS` | список Telegram ID администраторов через запятую |
